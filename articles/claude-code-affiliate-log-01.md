## やったこと

### リポジトリを「唯一の正」にした

方針（CLAUDE.md）、手順（prompts/）、執筆と商品の見せ方のルール（rules/）、スクリプト（scripts/）、現状と決定ログ（docs/）を、すべて GitHub の kominka-ops リポジトリに置きました。手元の Claude Code も、claude.ai のクラウドルーティンも、同じファイルを読んで動きます。claude.ai 側のプロンプトは「認証情報と、このリポジトリの該当ファイルを読んで従え」だけです。ルールを変えたいときはファイルを変えて push するだけになりました。

### 日次ルーティンを1日2回にした

06:00 と 18:00 に動きます。手順は prompts/daily.md にあり、要約するとこの順番です。

1. docs/requests.md にある人からの未消化の依頼を最優先で反映する
2. GA4 と Search Console のレポートを生成する
3. カテゴリごとのハブ記事に、直近7日の新記事へのリンクを追記する
4. インデックス状況を確認する
5. テーマ選定をサブエージェントに委ね、記事ごとにサブエージェントを並列で起動して下書きを保存する
6. 商品カード化、meta description の長さ確認、アイキャッチ生成、docs/status.md の更新と push

### 作業ブランチを GitHub Actions で自動マージ

クラウドルーティンは実行環境の制約で main に直接 push できません。docs の更新が作業ブランチに取り残される事故が2回続いたので、`claude/**` への push をトリガーに main へ取り込むワークフローを置きました。

```yaml
      - name: merge
        run: |
          git fetch origin "$SRC"
          if git merge --no-edit -X theirs "origin/$SRC"; then
            git push origin HEAD:main
            echo "merged=true" >> "$GITHUB_OUTPUT"
          else
            git merge --abort || true
            echo "merged=false" >> "$GITHUB_OUTPUT"
          fi
```

競合したらルーティン側を優先し、それでも取り込めなければ Pull Request を作って私に知らせます。

### 週次レビューはルール変更を Pull Request で出す

週次レビューは `review/<日付>` ブランチに rules/ と prompts/ の差分を作り、PR にします。私はマージかクローズを選ぶだけです。今週のレビューは「実績データが1週間分しかないので提案なし」でした。

### 人からルーティンへの一時依頼

「今回だけ書いてほしい記事」のような依頼は docs/requests.md に書きます。ルーティンは実行の冒頭でここを読み、着手したら「対応中」に移して push し、終わったら「消化済み」に書き換えます。初回の依頼は「A8.net の提携済み案件を主役にした記事4本」でした。

- 今週の楽天クリック547回は KPI になりません。449回は同じ日に集中し、その日は52記事に商品カード化を適用して Bing へ57 URL を送信した日でした。GA4 のセッションは2件、クリックは141店に3〜7回ずつ分散していたので、クローラーかリンク検証によるものと判断しました。

## うまくいかなかったこと

1. **「全記事未インデックス」は誤診でした。** 開始8日目まで、インデックス確認スクリプトは全記事を「Google が知らない URL」と返していました。原因は WordPress の REST API が返す URL がパーセントエンコード済みで、そのまま URL Inspection API に渡すと別 URL として扱われることでした。修正は1行です。

   ```diff
   -        body = {"inspectionUrl": p["link"], "siteUrl": GSC_SITE_URL}
   +        body = {"inspectionUrl": urllib.parse.unquote(p["link"]), "siteUrl": GSC_SITE_URL}
   ```

   修正後の実測は52本中46本が登録済みでした。初回の週次レビューは誤った前提で「サイトマップ送信が最優先」と書いており、流入施策の方向を1週間ほど間違えていました。
2. **ルーティンが main に push できず、docs の更新が2回消えかけました。** 作業ブランチに取り残されたのを私が手でマージし、上記の GitHub Actions で対処しました。
3. **週次レビューが運用台帳への書き込みで17分止まりました。** Artifact の書き込みが承認待ちになるためです。台帳は読むだけにして、レビューは docs/reviews/ に置く運用に変えました。
4. **「ルーティンは下書きまで」が形だけになりかけています。** 今週は下書き12本を私がその日のうちに「公開して」と指示し、同じセッションが公開しました。自動公開はしていませんが、私の確認が薄くなっている自覚があります。
5. 小さな事故として、終了したセールを「開催中」と書いたままの記事が1本、同じテーマの下書きの重複が1本ありました。前者はルーティンが日付を更新し、後者は私が削除しました。
